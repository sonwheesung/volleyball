## 0. 목표와 한 줄 결론

- **목표**: 배구명가를 한국(KOVO) 넘어 **전세계 출시**. 선수 이름·외모·용병(국적)·UI/서사 언어를 현지화.
- **한 줄 결론**: 사용자가 지목한 "이름·외모·용병"은 실제 공수의 일부일 뿐이고, 지배적 비용은 **① UI+서사 다국어화(i18n) ② "외국인=예외" 엔진 전제 뒤집기** 두 XL 벽이다.
- **규모**: 1인 개발 기준 **가벼운 경로 최소 1~2개월 / 제대로 된 글로벌 3~6개월+** (아래 §5 로드맵으로 좁힘).

> 공수 등급: **S**=1~2일 · **M**=3~5일 · **L**=1~2주 · **XL**=3주+ (1인 개발 순차 작업 기준).

## 1. 영역별 현 상태 실측 (코드 근거)

### 1.1 선수 이름 — 잘 격리됨(가벼움)
- 절차적 음절 조합, 단일 파일 `data/names.ts`(176줄). 국내 `genKoreanName`(:109, SURNAMES 60), **외국인 `genForeignName`(:121)은 이미 유럽 여자풍**, 아시아쿼터 `genAsianIdentity`(:152, 8개국).
- **결정론 격리**: 이름은 `kname:`/`fname:`/`aname:` **서브스트림**에서만 추첨 → 스탯 rng와 분리. 다로케일 추가해도 **골든/시뮬 안 깨짐**.
- ⚠ **함정**: 음절 배열은 **append-only**(원소를 앞에 끼우면 인덱스가 밀려 기존 세이브의 미래 이름 결정론이 깨짐 — `names.ts:33,52` 명시 경고).
- ⚠ **세이브 박제**: 완성 이름이 `playerBase`·기록·명전에 **문자열로 영속**(`useGameStore.ts:1719`) → 신규 게임은 안전하나 "구 한국 세이브를 국제판 이름으로 전환"은 마이그레이션 필요.

### 1.2 팀·리그명 — 사실상 완료(S)
- `TEAM_NAMES`(`names.ts:167`) 7개 **전부 가상**("인천 타이드" 등, :166 주석). 실제 KOVO 구단명 참조 **없음**. 리그도 가상.
- ✅ **상표·퍼블리시티 리스크 선제 제거**: V리그 감독 실명 `COACH_NAMES`는 2026-07-21 폐기(`names.ts:163`), 가드 `_dv_coach3axis.ts`가 실명 유출 감시. 팀명은 세이브 미영속(teamId만 기록) → 리네임 마이그레이션 불요.

### 1.3 통화·숫자 표기 — 표시 중앙화(M), 내부 단위는 결합(주의)
- 표시 함수 2개로 중앙화: `formatMoney`(`salary.ts:123`)·`formatMoneyShort`(`money.ts:7`), 둘 다 `억`/`만` 하드코딩. **24개 파일**이 호출.
- ⚠ **내부 단위가 "만원" 정수로 엔진 전체에 박힘**: `BASE=24000`(`salary.ts:13`), 캡 상수, FA 카운터 스텝 등. 표시 로케일화(억/만↔K/M/B)는 **M**이지만, 실통화(USD 재스케일)는 엔진 상수 밸런스 재측정 유발 → **L**.

### 1.4 외모·아바타 — 코딩 M·에셋 XL
- **얼굴시트 크롭 스프라이트**: `assets/players/faces1~34.png`(34장 3×3, **768²·합계 29MB**, 2026-07-29 경량화). 배정 = `faceHash(id)%306`(`faceSheetMeta.ts:15`), id 시드 결정론·무저장. 렌더 `PlayerAvatar.tsx`는 **`id`만 입력**(국적/인종/성별 무관).
- **현 범위 = 전부 한국/아시아 여성**(`AVATAR_SYSTEM.md:17` "여자 V리그 톤·여성형 헤어"). 피부 팔레트도 밝은~중간 아시아톤만(`playerFace.ts:7`).
- **국적↔외모 무연동 부조화**: 서양 용병(브라질·튀르키예 홈리그)이 **아시아 여성 얼굴**을 랜덤 배정받음. `Player.nationality`는 이미 존재하나(§1.5) 아바타가 안 읽음.
- 에셋 파이프라인 = **생성형 AI + 오프라인 키잉**(`tools/keyFaces.ts`), 리드타임 34장에 ~2주.

### 1.5 외국인·국적 — 엔진 리팩터(XL)
- **국적이 1급 데이터가 아님**: `types/index.ts:63-65` — `isForeign: boolean`(필수)·`isAsianQuota?`·`nationality?`(아시아쿼터 표시용만). 일반 외국인 OP·국내 선수는 국적 없음.
- **"외국인=예외" 하드코딩 지도**: 팀당 외인 1(OP)+아시아 1(`seed.ts:404`), `IMPORT_SLOTS=2`(`rosterTarget.ts:27`), 외인 연봉 균일·캡 제외(`foreign.ts:16` `FOREIGN_SALARY=41000`, `cap.ts` `!isForeign`), FA 비대상·방출 시 리그 이탈·연고 없음·정년 별도 루프. 즉 **`!isForeign` 단락(short-circuit)이 캡·FA·정원·연고·방출·정년 수십 곳**에 박힘.
- 글로벌("리그 X 외국인 = 리그 Y 국내")에선 이 이진 전제가 붕괴 → 각 `!isForeign`을 **"이 선수가 이 리그 규정상 수입 슬롯을 먹는가"** 문맥 판정으로 전환해야 함(XL). 문서 §7.4가 "리졸버를 slot-kind+티어 파라미터로" 일반화 방향을 이미 예고(부분 포석).

### 1.6 UI·서사 다국어화(i18n) — 지배적 비용(XL)
- **인프라 전무**: `i18next`/`expo-localization` 등 **의존성 0, import 0**(`package.json`). 로케일 감지 수단조차 없음 → 바닥부터.
- **정적 UI 문자열**: `app/` 3,371 한글줄/60파일 + `components/` 1,773/55 = **~5,144줄/115파일/57화면**. 추출·키화·번역은 기계적이나 규모가 큼(**L**).
- **동적 서사 = 번역 아닌 재작성(XL)**: 한국어 조사 엔진 `lib/josa.ts`(받침→이/가·을/를)가 **서사 11개 파일에 하드 결합**(news·contracts·fa·draft 등). 뉴스 엔진 `data/news.ts`(502줄)가 SOV 템플릿을 코드로 조립. `${변수}한글` 조립 **1,158곳/338파일**. 영어는 어순·복수형·관사가 달라 **문장 생성기 자체를 언어별 재설계**해야 함.
- 약관/개인정보 `data/legalText.ts`(195줄)는 번역이 아니라 **국가별 법무 현지화**(별도 비용).

## 3. 두 개의 XL 벽 (여기서 대부분의 시간이 감)

1. **서사 다국어화 = 재작성**: 받침 조사·SOV 어순·억/만이 뉴스/시상/오프시즌 문장 생성에 박혀 있어, 영어화는 "치환"이 아니라 **언어별 문장 생성기 재설계**.
2. **"외국인=예외" 전제 붕괴**: 외국인을 국내 경제/FA/정원에서 빼는 예외로 박아둔 걸, 리그 규정 함수로 전환 + **밸런스 배터리(simLeague/simForeign/simAudit) 전면 재튜닝**.

## 4. 리스크

1. **밸런스 회귀(최상)**: 외국인 캡 제외가 국내 FA parity를 지탱(`IMPORT_RETAIN_ATTRITION=0.70`으로 겨우 튜닝). 수입 판정 일반화 시 캡 합산 대상이 바뀌어 전 시뮬 배터리 재측정 불가피.
2. **세이브/결정론**: `nationality` 필수화·수입 판정·시드 스트림 소비 변경 = 스냅샷 스키마 변경 → 버전 범프+마이그레이션. 현 "무마이그레이션(자가치유)" 전제가 깨짐. 이름/얼굴이 세이브에 박제·재배정.
3. **얼굴 전면 재배정**: 시트 풀을 바꿔 `FACE_TOTAL`/산식이 변하면 `id%전체수` 매핑이 전면 재배정 → **기존 유저의 정든 선수 얼굴이 전부 바뀜**(`AVATAR_SYSTEM.md:11` 인정). 완화: 신규 인종은 **별도 버킷**으로 추가하고 기존 아시아 인덱스는 보존.
4. **콘텐츠 물량**: 다인종 얼굴 에셋 + 다국어 서사 문안은 코딩과 별개로 수 주~수개월의 지속 제작.
5. **법무**: 국가별 약관·개인정보·연령·결제 규정 현지화(한국 게임법 대응과 별개).

## 5. 로드맵 옵션 (결정 변수로 공수가 갈림)

**결정 변수 3개**(미정 — 아래를 정해야 견적이 좁혀짐):
- **(a) 지원 언어 수** — 영어 1개 vs 다국어.
- **(b) 구 한국 세이브 전환 여부** — 신규 게임만 국제판(안전) vs 기존 세이브도 전환(XL 마이그레이션).
- **(c) 얼굴 국적 정합** — 다양성만 추가(정합 포기, 코딩 S) vs 국적↔외모 연동(코딩 M + 에셋 XL).

### 옵션 A — 가벼운 경로(MVP 글로벌)
영어 1개 + 신규 세이브만 + 얼굴 "다양성만 push"(정합 포기) + 외국인 규정 KOVO 유지.
- 포함: i18n 인프라 + 정적 문자열(L) + **동적 서사 영어화(XL, 여기가 대부분)** + 이름 영어풀(M) + 통화 표시(M) + 얼굴 시트 일부 다양화(에셋).
- **예상: 최소 1~2개월+**(서사 i18n이 바닥). 외국인 국적 축·엔진 일반화는 **미포함**(추후).

### 옵션 B — 제대로 된 글로벌
옵션 A + 국적 1급 데이터화(M) + 외국인 규정 일반화(XL) + 얼굴 국적 연동(M+에셋 XL) + 밸런스 전면 재튜닝 + 다국어.
- **예상: 3~6개월+**. 관전형·누적서사·결정론 기둥은 유지(로컬라이제이션은 표시·데이터 계층이 원칙, 시드/리플레이 격리 준수).

### 권고 순서(착수 시)
1. **i18n 인프라 + 정적 문자열**(모든 경로의 전제) →
2. **동적 서사 영어 엔진**(가장 큰 덩어리, 조기 착수) →
3. 이름·통화 로케일화 →
4. (옵션 B면) 국적 축 + 외국인 일반화 + 밸런스 재튜닝 →
5. 얼굴 에셋(병렬 제작, 기존 인덱스 보존 버킷).

## 6. 이미 유리한 점 (선제 해결됨)
- ✅ 팀·리그·감독 **상표/퍼블리시티 리스크 없음**(전부 가상·실명 폐기).
- ✅ 외국인 이름 생성기가 이미 유럽풍 + 아시아쿼터 8개국 국적 체계 → **이름 확장 골격 존재**.
- ✅ 이름이 시드 서브스트림에 격리 → 다로케일 추가해도 **골든/시뮬 무회귀**.
- ✅ 통화 표시가 함수 2개로 중앙화 → 표시 로케일화 지점이 좁음.

## 7. 미결 질문 (착수 전 결정)
- Q1. 지원 언어 범위(영어만? 일·중 등?) — (a).
- Q2. 구 한국 세이브 국제판 전환 여부 — (b). (기술: 이름 문자열 박제 마이그레이션 난이도.)
- Q3. 얼굴 국적 정합 수준 — (c). (기존 유저 얼굴 보존 위해 버킷 설계 필수.)
- Q4. 외국인 모델을 KOVO 유지 vs 리그별 일반화 — 옵션 A/B 분기.
- Q5. 통화: 표시만 로케일화 vs 실통화 재스케일(밸런스 재측정 유발).
- Q6. 서사 i18n 접근: 언어별 템플릿 재작성 vs 서사 톤 단순화(조립 최소화)로 i18n 부담 경감할지.
